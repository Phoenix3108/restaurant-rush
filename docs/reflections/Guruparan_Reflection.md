# Reflection: Guru (Menu and Class Diagram Contributions)

## What I worked on

I did the Menu functionality and class diagram documentation for the Restaurant Rush project.

For the Menu component I did the Menu related classes and their functionality (menu items, getting of menu items etc) and the various features that were introduced across the stages. As we went through the project I did the work on the most expensive menu item and the combo meals.

I was also responsible for the creation and maintenance of the UML class diagrams for all three stages using Plantuml. The diagrams were kept in line with the actual implementation of each stage (including any changes to classes, methods, attributes and relationships) and I incorporated the feedback from the team as we went. They were finally exported as PNGS for inclusion in the report.

## What went well

- Working on Menu helped me to understand how the various classes interact to provide the functionality.
- PlantUML was used which made it far easier to create and update the class diagrams.
- Having separate diagrams for all three stages was useful in illustrating the progression of the system.
- Incorporating feedback from our team went a long way to improving the accuracy and completeness of the diagrams.

## What was difficult

- Keep the class diagrams in line with the actual implementation at all stages.
- Understanding how the new features impacted the existing classes and their relationships.
- Correctly representing concepts of inheritance, composition and multiplicities.
- Coordinating the changes with the team as we worked towards the final deadline.

## What I learned

- Gained hands on experience with Java and OOP.
- I've learned how to produce UML class diagrams using PlantUML.
- Improved my understanding of inheritance, encapsulation, polymorphism and composition.
- I got much more comfortable with Git and GitHub for collaboration and version control.

## What I would do differently

I'd be documenting the system much earlier and updating the diagrams as the implementation changes. I'd spend a lot more time understanding the architecture as a whole prior to making any changes, which would in turn reduce the number of last minute fixes. I'd also be far more proactive in communicating with and coordinating changes with the team to avoid any integration issues.
